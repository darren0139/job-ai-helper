**A1 proposal:** whole-phrase `restful apis`, guarded against recognized product-name spans, additive to existing variants and fallback. Keep develop+integrate and develop+consume conjuncts, front-end scope, efficiency/security and framework examples intact. REST/gRPC AND/OR, alternatives, negation and optional obligations cannot be simplified to an easier REST-only requirement. Existing API evidence rules remain; any missing modifier/complete-parent credit contract requires separate scope approval before activation.

**Positive controls:** “Collaborate with stakeholders” is an S1 recognition candidate; “Experience building RESTful APIs” already resolves through the approved fallback; qualified RESTful API development is an A1 review candidate. **Negative controls:** general unnamed teamwork, RESTfulness (not a whole API phrase), AWS product names. **Counterexamples:** S0 mechanically recognizes “Generate dashboards for stakeholders” and “Do not collaborate with stakeholders”; A1 mechanically recognizes reading/negation and API+database compound requirements. “Consume RESTful APIs” can identify API-related activity but cannot establish development authorship.
